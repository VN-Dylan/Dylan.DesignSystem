# Theming & Modes

Three independent axes, all resolved at **runtime** by rewriting `--dyl-*`
custom properties — never by rebuilding CSS.

<Markdown>{`
| Axis | Mechanism | Persists to |
| --- | --- | --- |
| Colour mode | \`.dark\` class on \`<html>\` (Tailwind \`darkMode: 'class'\`) | \`localStorage\` |
| Brand schema | \`data-theme-schema\` + inline CSS variables on \`<html>\` | \`localStorage\` |
| Direction | \`dir\` attribute + CSS logical properties | \`localStorage\` |
`}</Markdown>

Use the Storybook toolbar (top) to flip light / dark — every component page and
every swatch in **Design Tokens** re-reads the live values.

---

## Dark mode

`:root.dark` re-declares the semantic surface / text tokens and the status
`*-subtle` tints (which become alpha overlays instead of flat colours). Brand
hues stay put. In a consuming app:

```ts
import { useDarkMode } from '@dylan-ds/utils'

const { isDark, toggle } = useDarkMode() // toggles `.dark`, persists
```

Or manually:

```ts
document.documentElement.classList.toggle('dark', isDark)
```

## Preset brand schemas

Eight schemas ported from Eyris — `default`, `dark`, `green`, `purple`,
`orange`, `cyan`, `gold`, `pink`. Each overrides only the **primary family**
(`primary`, `primary-deep`, `primary-mild`, `primary-subtle`, `on-primary`) for
both light and dark.

```ts
import { useThemeSchema } from '@dylan-ds/utils'
useThemeSchema('green', 'light') // writes vars to <html>, persists

// or the token layer directly:
import { presetThemeSchema, themeSchemaToCssVars } from '@dylan-ds/tokens'
const vars = themeSchemaToCssVars(presetThemeSchema.green.light)
Object.entries(vars).forEach(([k, v]) => document.documentElement.style.setProperty(k, v))
```

The showcase app owns the higher-level theme _store_ (zustand) that ties these
together; the packages only expose the primitives.

export const SchemaSwitcher = () => {
  const [schema, setSchema] = useState('default')
  useEffect(() => {
    const value = presetThemeSchema[schema]?.light
    if (!value) return
    const root = document.documentElement
    const vars = themeSchemaToCssVars(value)
    for (const [prop, val] of Object.entries(vars)) root.style.setProperty(prop, val)
    return () => {
      // reset to the default schema on unmount so the rest of the page/docs
      // aren't left on a brand hue this demo picked
      const fallback = themeSchemaToCssVars(presetThemeSchema.default.light)
      for (const prop of Object.keys(fallback)) root.style.removeProperty(prop)
    }
  }, [schema])
  return (
    <div style={{ margin: '1rem 0' }}>
      <div style={{ display: 'flex', flexWrap: 'wrap', gap: '0.5rem', marginBottom: '0.75rem' }}>
        {themeSchemaNames.map((name) => (
          <button
            key={name}
            type="button"
            onClick={() => setSchema(name)}
            style={{
              display: 'flex',
              alignItems: 'center',
              gap: '0.4rem',
              padding: '0.35rem 0.6rem',
              borderRadius: 'var(--dyl-radius-md)',
              border: `1px solid ${schema === name ? 'var(--dyl-primary)' : 'var(--dyl-border)'}`,
              background: schema === name ? 'var(--dyl-primary-subtle)' : 'var(--dyl-surface)',
              color: 'var(--dyl-text)',
              cursor: 'pointer',
              fontSize: '0.8rem',
              textTransform: 'capitalize',
            }}
          >
            <span
              aria-hidden
              style={{
                width: 12,
                height: 12,
                borderRadius: '999px',
                background: presetThemeSchema[name].light.primary,
              }}
            />
            {name}
          </button>
        ))}
      </div>
      <div
        style={{
          display: 'flex',
          gap: '0.75rem',
          alignItems: 'center',
          padding: '1rem',
          borderRadius: 'var(--dyl-radius-lg)',
          border: '1px solid var(--dyl-border)',
          background: 'var(--dyl-surface)',
        }}
      >
        <button
          type="button"
          style={{
            padding: '0.5rem 1rem',
            borderRadius: 'var(--dyl-radius-md)',
            border: 'none',
            background: 'var(--dyl-primary)',
            color: 'var(--dyl-on-primary)',
            fontSize: '0.85rem',
          }}
        >
          Primary button
        </button>
        <span
          style={{
            padding: '0.3rem 0.6rem',
            borderRadius: 'var(--dyl-radius-full)',
            background: 'var(--dyl-primary-subtle)',
            color: 'var(--dyl-primary)',
            fontSize: '0.75rem',
          }}
        >
          Subtle tag
        </span>
      </div>
    </div>
  )
}

## RTL

```ts
import { useDirection } from '@dylan-ds/utils'
const { direction, toggle } = useDirection() // sets dir="rtl" on <html>
```

Component SCSS uses **logical properties** throughout — both the plain-CSS rules
(`margin-inline-start`, `inset-inline`, `border-inline-start`) and the Tailwind
`@apply` layer (`ps-*` / `pe-*` / `ms-*` / `me-*` / `start-*` / `end-*` /
`text-start` / `rounded-s-*` / `border-s`). Layout mirrors with no per-component
work; the few transform-based offsets (Switcher thumb, Badge dot) carry an
explicit `rtl:` override.

Use the **Direction** toolbar control in Storybook to preview any story in RTL.

Deliberately physical (not mirrored): `Drawer` `placement="left|right"` (the prop
names a side), the `Slider` fill track (value runs min→max left-to-right), the
`GanttChart` timeline, and glyph shapes like the checkbox tick.

## Applying the system in a consuming app

```ts
// 1. tokens as CSS vars + the component styles
import '@dylan-ds/tokens/css'
import '@dylan-ds/ui/styles.css'
```

```ts
// 2. the Tailwind preset, so utility classes resolve
import { dylanPreset } from '@dylan-ds/tokens/tailwind-preset'
export default {
  presets: [dylanPreset],
  content: ['./src/**/*.{ts,tsx}', './node_modules/@dylan-ds/ui/dist/**/*.js'],
}
```

## Charts follow the theme too

`<Chart>` reads its colours, gridlines and tooltip theme straight from the live
`--dyl-*` values and re-reads them (via a `MutationObserver` on `<html>`) when
the mode or schema changes — so a dashboard stays on-brand in every theme with
no per-chart configuration.

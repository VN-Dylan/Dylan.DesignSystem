# Dylan Design System

A production-oriented React component system. It reproduces the **component
surface of the Eyris admin template** — 42 base components, 42 composite
components, 32 utilities — as an independent, self-contained library with **no
external UI-kit dependency**, built on React 18, Tailwind CSS v3, SCSS and
TypeScript.

It is an **internal** system. Component and prop names mirror Eyris for API
familiarity; all brand assets, copy and visual identity are Dylan's own.

## Where documentation lives

- **This handbook** (`Handbook/*`) — the _why_: principles, tokens, theming,
  accessibility, API conventions, the Eyris mapping.
- **Component pages** (`Common/*`, `Data Display/*`, `Forms/*`, `Feedback/*`,
  `Navigation/*`, `Primitives/*`, `Composite/*`) — the _how_: one autodoc page
  per component, a story per Eyris demo, a prop table generated from TSDoc.
- `DESIGN.md` (repo root) — the single source of truth this handbook is drawn
  from. `RECIPE.md` — the contract every component is built to.

## Reading order

1. **Architecture** — the styling split and how a component reaches a bundle.
2. **Principles** — the five rules everything else follows from.
3. **Design Tokens** — the values. Nothing in the system is a literal.
4. **Theming & Modes** — light / dark / RTL / 8 brand schemas, all at runtime.
5. **Accessibility** — the baseline, and why it's an acceptance criterion.
6. **Component API** — the shapes you'll see on every component.
7. **When to Use What** — picking between components that solve similar problems.
8. **Contributing** — how a new component gets built.
9. **Eyris Mapping** — the Eyris ↔ Dylan map, including the deliberate deviations.

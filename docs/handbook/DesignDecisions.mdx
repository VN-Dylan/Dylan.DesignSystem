# Design decisions

The library aims for a familiar, conventional component API. This page records
the places where a component **deliberately** does something its common
counterpart in other admin kits does not — and why.

## Components

<Markdown>{`
| Component | Decision | Why |
| --- | --- | --- |
| \`Button\` | no \`asChild\` / polymorphic \`as\` | Keeps the ref + \`data-*\` contract simple. Navigate with an \`onClick\` handler that calls \`navigate\`. |
| \`Calendar\` · \`DatePicker\` | \`labelFormat\`/\`monthLabelFormat\`/\`yearLabelFormat\` are stubbed | Day/month/year grids all have a roving tab stop + arrow/Home/End keyboard nav; the header label cycles date → month → year (\`enableHeaderLabel\`, \`defaultView\`). Custom label-format strings are out of scope for the internal use cases. |
| \`FullCalendar\` | dependency-free **month view only** — no week/day/list views, no drag | Avoids a heavy calendar dependency. |
| \`GanttChart\` | dependency-free implementation | Same reason. Bars, progress fill, a shared date axis. |
| \`VectorMap\` | choropleth ramp is interpolated **in-component** and fed as a code→hex map | jsvectormap 1.6 only ships an ordinal (lookup) scale, not a numeric one. |
| \`DataTable\` | no \`onRowClick\` prop | Views delegate a click on a wrapping element; a first-class prop is a follow-up. |
| \`Select\` · \`Segment\` | width must be constrained by a wrapper element | The component sets \`width: 100%\`, which beats a utility class on the component itself. |
| \`Select\` | lean custom control — no \`creatable\`, custom option/label renderers, group labels, \`onMenuOpen\`/\`onInputChange\`; \`disabled\` instead of \`isDisabled\` | A dependency-free control covering the shapes the showcase needs, instead of wrapping \`react-select\`. |
| \`Table\` | \`borderless\` (inverted) instead of \`bordered\`; no \`asElement\`, \`overflow\`/\`overflowClass\`, \`verticalDivider\` | Overflow/scroll is the caller's container concern; column dividers weren't used. |
| \`Toast\` | single \`placement\` prop instead of offset / transition tuning | Nine fixed placements cover the need. |
| \`Upload\` | no \`fileListClass\` / \`fileItemClass\` | Style the composed list element via its \`className\`. |
| \`Input\` | \`onChange\` / \`onFocus\` / \`onBlur\` aren't in the prop table — they pass straight through | Every primitive spreads native props/events onto its main node. |
| \`Chart\` | grid / palette / tooltip are house-styled and theme-reactive rather than ApexCharts defaults | Faint horizontal-only gridlines, an interleaved categorical palette, and a \`MutationObserver\` that re-reads tokens on theme change. |
| \`Dialog\` · \`Drawer\` | \`title\` and \`footer\` are pinned; only the body scrolls; height capped at the visible viewport (\`dvh\`) | Save / Cancel must never need a scroll, on any device. |
| Floating menus | \`Select\`, \`Combobox\`, \`AutoComplete\`, \`Dropdown\` render on the popover layer | They open inside dialogs and drawers. |
`}</Markdown>

| \`Combobox\` | forms | WAI-ARIA 1.2 combobox with debounced, abortable remote search and tag-style multi-select. |
| \`AccessProvider\` · \`Can\` · \`useAccess\` | permissions | Role → permission gating with wildcards; hide or disable. See **Permissions & Auth**. |

| \`Center\` · \`Spacer\` · \`AspectRatio\` | layout | Minimal centering, flex filling and aspect-ratio primitives. |

| \`Card\` | spacing | Default inner padding is 24px (\`p-card\`); \`padding="compact"\` uses 16px. |
| \`Divider\` | spacing | Explicit \`spacing\`; horizontal labels render between two lines. |
| Spacing normalization | spacing | Off-scale padding/gap values snapped to the 4px-based scale across inputs, tables, drawers and cards. |
`}</Markdown>

The documented API is reconciled in CI: `pnpm check:api` diffs every documented
prop against the component source and fails on an unlisted gap.

## Utilities

3 utilities are **app-coupled** and live in `apps/showcase/src/utils` rather
than `@vn-dylan/utils`, because they depend on the auth store / layout config /
navigation tree: `useAuth` · `useLayout` · `useMenuActive`.

The table / URL hooks **are** in `@vn-dylan/utils`, implemented against the
History API so they carry no router dependency:

<Markdown>{`
| Hook | Purpose |
| --- | --- |
| \`useAppendQueryParams\` | Merge / override / clear URL query params; \`replace\` for no history entry. |
| \`useQueryParamPagingState\` | Read a \`DataTable\`'s page / size / sort / query out of the URL; \`filterState\` collects the rest. |
| \`useDataTableState\` | Local paging + sort + selected-row state with handlers shaped for the \`DataTable\` props. |
| \`withHeaderItem\` | HOC — wrap a component as a \`role="button"\`, keyboard-operable header-bar item. |
`}</Markdown>

`useTranslation` in `@vn-dylan/utils` is a **stub** (returns the key). Component
strings are translated by `LocaleProvider`; app strings belong to the app (the
showcase ships a typed `useTranslation` in `src/i18n`).

## Bundle

`@vn-dylan/ui` ships as **per-module chunks** (`preserveModules`) so a consuming
app only bundles what it imports. Vendor libraries are kept **external**
(ApexCharts, TanStack Table, Tiptap, jsvectormap, react-syntax-highlighter are
peer deps of the consuming app), as is every `react-icons` subpath.

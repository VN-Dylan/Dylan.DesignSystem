# Eyris ↔ Dylan

The system reproduces the Eyris component surface **1:1 by name**. An Eyris
`<Button variant="solid" />` is a Dylan `<Button variant="solid" />`. The import
alias changes from `@/components/ui/<Name>` to `@vn-dylan/ui`; everything else is
meant to feel identical.

This page records where that is **deliberately not** true.

---

## Deliberate deviations

### Components

<Markdown>{`
| Component | Deviation | Why |
| --- | --- | --- |
| \`Button\` | no \`asChild\` / polymorphic \`as\` | Keeps the ref + \`data-*\` contract simple. Navigate with an \`onClick\` handler that calls \`navigate\`. |
| \`Calendar\` · \`DatePicker\` | \`labelFormat\`/\`monthLabelFormat\`/\`yearLabelFormat\` are stubbed | Day/month/year grids all have a roving tab stop + arrow/Home/End keyboard nav; the header label cycles date → month → year (\`enableHeaderLabel\`, \`defaultView\`). Custom label-format strings are out of scope for the internal use cases. |
| \`FullCalendar\` | dependency-free **month view only** — no week/day/list views, no drag | Avoids a heavy calendar dependency. |
| \`GanttChart\` | dependency-free re-implementation | Same reason. Bars, progress fill, a shared date axis. |
| \`VectorMap\` | choropleth ramp is interpolated **in-component** and fed as a code→hex map | jsvectormap 1.6 only ships an ordinal (lookup) scale, not a numeric one. |
| \`DataTable\` | no \`onRowClick\` prop | Views delegate a click on a wrapping element; a first-class prop is a follow-up. |
| \`Select\` · \`Segment\` | width must be constrained by a wrapper element | The component sets \`width: 100%\`, which beats a utility class on the component itself. |
| \`Select\` | lean custom control — no \`creatable\`/\`isCreatable\`, \`customOption\`/\`customLabel\`/\`customInputDisplay\`, \`formatGroupLabel\`, \`onMenuOpen\`/\`onInputChange\`, \`searchInputProps\`, \`showClearAllButton\`, \`isDisabled\` (use \`disabled\`) | Eyris wraps \`react-select\`; Dylan ships a dependency-free control covering the shapes the showcase needs. |
| \`Table\` | \`borderless\` (inverted) instead of \`bordered\`; no \`asElement\`, \`overflow\`/\`overflowClass\`, \`verticalDivider\` | Overflow/scroll is the caller's container concern; column dividers weren't used. |
| \`Toast\` | single \`placement\` prop instead of \`offsetX\`/\`offsetY\`/\`block\`/\`transitionType\` | Nine fixed placements cover the need; offset/transition tuning removed. |
| \`Upload\` | no \`fileListClass\` / \`fileItemClass\` | Style the composed list element via its \`className\`. |
| \`Input\` | \`onChange\` / \`onFocus\` / \`onBlur\` aren't in the prop table — they pass straight through | Every primitive spreads native props/events onto its main node. |
| \`Chart\` | grid / palette / tooltip are Eyris-styled and theme-reactive rather than ApexCharts defaults | Faint horizontal-only gridlines, an interleaved categorical palette, and a \`MutationObserver\` that re-reads tokens on theme change. |
`}</Markdown>

### Beyond Eyris

<Markdown>{`
| Component | Deviation | Why |
| --- | --- | --- |
| \`Rating\` | booking-readiness addition, not in the Eyris crawl | Booking detail pages need an accessible star score and input primitive. |
| \`PriceTag\` | booking-readiness addition, not in the Eyris crawl | Booking cards and detail pages need locale-aware price formatting with discount and unit text. |
| \`ImageGallery\` | booking-readiness addition, not in the Eyris crawl | Booking detail pages need responsive media grids with an accessible lightbox viewer. |
| \`MapView\` | booking-readiness addition, not in the Eyris crawl; adds optional \`maplibre-gl\` peer dependency | Booking search and detail pages need an accessible live map wrapper that remains safe without a tile URL. |
| \`AvailabilityCalendar\` | booking-readiness addition, not in the Eyris crawl | Lodging detail pages need range selection with availability, stay-length, and nightly-price affordances. |
| \`GuestSelector\` | booking-readiness addition, not in the Eyris crawl | Booking search and checkout forms need category-based guest and room counts in a compact popover. |
`}</Markdown>

Reconciliation is enforced: \`pnpm check:api\` (in CI) diffs every documented prop
in the \`docs/reference/eyris-crawl\` JSON against the component source and fails
on an unlisted gap. 38 base components, 433 props.

### Utilities

3 utilities are **app-coupled** and live in `apps/showcase/src/utils` rather
than `@vn-dylan/utils`, because they depend on the auth store / layout config /
navigation tree: `useAuth` · `useLayout` · `useMenuActive`.

The table / URL hooks **are** in `@vn-dylan/utils`, re-implemented against the
History API so they carry no router dependency (Eyris binds them to
react-router):

<Markdown>{`
| Hook | Purpose |
| --- | --- |
| \`useAppendQueryParams\` | Merge / override / clear URL query params; \`replace\` for no history entry. |
| \`useQueryParamPagingState\` | Read a \`DataTable\`'s page / size / sort / query out of the URL; \`filterState\` collects the rest. |
| \`useDataTableState\` | Local paging + sort + selected-row state with handlers shaped for the \`DataTable\` props. |
| \`withHeaderItem\` | HOC — wrap a component as a \`role="button"\`, keyboard-operable header-bar item. |
`}</Markdown>

`useTranslation` ships as a **stub** (returns the key) — i18n wiring is the
consuming app's job.

### Styling

<Markdown>{`
| Eyris | Dylan | Note |
| --- | --- | --- |
| \`bg-primary/40\` opacity modifier | supported on \`primary\` / \`success\` / \`error\` / \`info\` / \`warning\` / \`content\` / \`gray\` | Those colours ship a \`--dyl-*-channel\` R G B triplet and resolve through \`rgb(var(...) / <alpha-value>)\`. \`surface\` / \`border\` / \`bg\` / \`overlay\` stay solid-only — use \`-subtle\`, \`overlay\`, or \`brightness-*\` there. |
| brand identity, copy, logo | Dylan's own | The system mirrors the API, not the visual identity. |
`}</Markdown>

## Bundle

`@vn-dylan/ui` ships as **per-module chunks** (`preserveModules`, ~227 kB total,
largest chunk ~12 kB) so a consuming app only bundles what it imports. Vendor
libraries are kept **external** (ApexCharts, TanStack Table, Tiptap, jsvectormap,
react-syntax-highlighter are peer deps of the consuming app), as is every
`react-icons` subpath.
